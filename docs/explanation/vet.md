# 结果可信度判断

这一页解释 SeeSea 为什么在读取页面之前先判断网址，判断依据是什么，以及为什么它宁可漏掉一些，也不去误伤正常站点。配置见 [`[vet]`](../reference/config.md)，操作见[把钓鱼站挡在结果之外](../how-to/keep-phishing-out.md)。

## 要解决的问题

上游搜索引擎的排名不由我们决定。一个钓鱼页在某个引擎里排得靠前，我们就会拿到它。对给 AI 智能体用的搜索来说，这有两层代价：用户在结果里看到一个假的登录页，智能体还会去下载这个页面，页面里的文字有可能是针对智能体写的指令。

所以判断必须发生在读取之前，只能依据网址本身，并且要快：一次搜索有几十个候选，每个候选不能多花一次网络请求。

## 它判断什么

判断分三类依据，全部在本机完成。

**热门度。** 数据来自 Tranco 榜单，一百万个域名。前一万名叫巨头，前十万名叫知名站点，榜内其余叫榜内站点，不在榜内的是未上榜。知名站点上的 `login`、`paypal`、`account` 都是正常内容，paypal.com 本来就有登录页，所以对前十万名的站点，凡是基于名字和路径的怀疑一律关闭。

**官方站点。** 内置约五百家知名品牌的自有域名。网址属于品牌自己的域名时，加分并在结果里标出 `official`。

**钓鱼信号。** 都只看网址：

- 知名域名被写进子域名，如 `accounts.google.com.session-check.example`。
- 品牌名出现在不属于品牌的域名里，如 `paypal-secure-login.example.com`、`binanceuz.co`。
- 和前五千名只差一两个字母，或用相似字符替换（`g00gle`）。
- 同一个名字里混用多种文字（拉丁字母加西里尔字母），裸 IP 作主机，`@` 前面放域名，短链接，随机生成的名字（包括免费托管上 `2r8p2e-qw444a-2p1k8z2m4s` 这类由随机片段连成的项目名），被滥用的顶级域名。

**页面内容。** 标准模式本来就会下载页面，读完之后再看页面自己露出的特征，不需要多发请求：

- 页面有密码或银行卡输入框，表单却提交给另一个站点（`form_elsewhere`）。
- 标题或首个大标题写着某个品牌的登录页，网址却不属于这个品牌（`brand_login_page`）。
- 页面是浏览器“另存为”的副本（`saved_copy`），有隐藏的 iframe（`hidden_iframe`），自动跳转到别的站点（`refresh_elsewhere`）。
- 托管平台自己的拦截页，例如 Cloudflare 的“Suspected Phishing”（`host_warning`）。

热门站点和品牌自己的域名不做这一步：它们的登录表单就是它们自己的。网址本来就可疑的页面，只要看到密码表单就会更低分；网址看不出问题的页面，只有表单提交给陌生站点或标题仿冒品牌才扣分，普通站点的登录页不受影响。读到页面后得到的判断会替换网址阶段的判断，所以结果里的 `level` 和 `flags` 是两者合起来的。

另外有两类名单：本地保存的威胁列表（默认 Phishing.Database，可加 OpenPhish），命中的网址直接剔除；你自己的 `allow` 和 `block`，优先于其余一切。

每个判断都带一串原因代码，所以任何一次误判都能追到是哪个信号造成的。

## 怎么算分

分数从 50 起，信任加分、怀疑减分，最后落在 0 到 100：不高于 25 是 `risky`，不高于 42 是 `suspicious`，不低于 65 是 `trusted`，其余是 `neutral`。命中威胁列表或 `block` 的是 `blocked`。

对排序的影响很小，而且有上限：

| 情况 | 第一层加减 | 最终分数加减 |
|---|---|---|
| 官方站点（在档位加分之外再加） | +0.06 | +0.03 |
| 巨头 | +0.06 | +0.03 |
| 知名站点 | +0.04 | +0.02 |
| `suspicious` | -0.2 | -0.1 |
| `risky` | -0.6 | -0.3，且不读取页面 |

加分故意很小。最终分数的 0.7 来自页面是否回答了问题，热门站点只能在相关度接近时胜出，不能压过更相关的小站。

## 几条防误伤的规则

这些规则是用真实榜单测出来的。拿 Tranco 的一百万个域名，每三个取一个，当作搜索结果来判断：

- 前十万名的站点三万三千个，没有一个被怀疑。
- 榜内其余站点三十万个，约 0.7% 被标为可疑或高风险，抽查大多是博彩仿站、成人站和 `google1102.com` 这类名字。

得到这个结果靠的是下面几条：

- **榜内站点需要第二个理由。** 榜单里也有被滥用的域名（`binanceuz.co` 在榜上），也有名字不凑巧的正常小站（`killedbygoogle.com`）。所以对前十万名之外的榜内站点，名字类信号的分值减半，除非还有别的信号同向，比如被滥用的顶级域名、随机名字或多个登录关键词。
- **路径单独不能让网址变可疑。** 路径里出现 `login`、`verify`，或者提到 microsoft，都很常见（一篇“如何重置 Microsoft 账号”的教程）。路径类信号加起来最多 7 分，只靠它们到不了 `suspicious`。品牌名本身也不算关键词。
- **平台上的用户站不继承平台的名次。** `someone.github.io`、`someone.weebly.com` 是各自独立的站点，按未上榜处理，否则放在这些平台上的钓鱼页反而拿到高分。平台自己的地址（`github.com`）保持原名次。
- **国家顶级域名不算风险。** 上游这份清单里有 `.cn`、`.ru` 这类，会把正常的中文和俄文站点都标成可疑。我们去掉了，只留 `.tk`、`.ml` 这些常被滥用的免费域名。其余的新通用顶级域名只作为佐证，单独只有 7 分，到不了 `suspicious`。
- **名字太短不比较。** 六个字母以下的名字离很多别的名字只差一个字母，十个字母以上才允许差两个。

## 和数据飞轮的关系

判断结果写进搜索日志：每个结果的等级、档位和原因代码都在 `journal` 里，第一层的 `score_parts.vet` 也在。这给后面的优化三样东西：

- 看哪个信号误伤了读过且相关的页面（`risky` 的页面不读取，但 `suspicious` 的会读，读完相关度高就是误伤的证据）。
- 看 `learned`（主机以往的表现）和 `vet` 是否一致。持续交付好内容的主机却被判可疑，说明信号该改。
- 用 `seesea feedback <网址> bad` 标出漏网的钓鱼站，再把它们的特征补进信号或加进 `block`。

`examples/calibrate` 可以在整份榜单上重新跑一遍分布，改了信号或权重后用它看有没有把误伤率推高。

## 实测效果

拿当天 OpenPhish 的 300 个新鲜钓鱼网址测过：

- 只靠网址信号，约 13% 被标为可疑或高风险。
- 加上 Phishing.Database 的域名列表（下载不完整，只用了一部分），命中列表的有 5%，合计约 19% 被拦下或标出。
- 其余约 80% 看不出问题：其中近一半放在 `pages.dev`、`vercel.app` 这类免费托管平台上，名字和路径都很普通。

另一份 3000 个网址的样本（来自 Phishing.Database 的链接列表）里，8% 判为 `risky`，7% 为 `suspicious`，4% 反而被判为 `trusted`，多是被入侵的 `.edu`、`.gov` 站点和短链服务本身。被入侵站点上的钓鱼套件现在会按路径特征取消顶级域名带来的信任（`kit_on_trusted_tld`），但这类情况只靠网址分辨不全。

所以它主要拦已知的和名字上明显仿冒的，对新出现的、放在免费托管上的钓鱼页作用有限。这类页面要读到页面内容才能判断，见下面的限制。

## 限制

- 页面内容只看服务器返回的静态 HTML。许多钓鱼页是单页应用，表单要靠脚本生成，静态 HTML 里什么也没有；渲染后的页面只有走了无头浏览器时才会被看到。抽样的 45 个 OpenPhish 页面里，静态 HTML 带表单的只有一半多，其中一部分是托管平台的拦截页。
- 新注册的钓鱼域名既不在榜内也不在威胁列表里，只能靠名字上的信号。威胁列表一般晚于首次出现几小时到几天。
- 品牌表以英语世界的品牌为主，中文互联网的品牌覆盖不够，可以用 `block` 补。
- Tranco 默认榜单混入了 Cloudflare Radar 的数据，该数据的许可限制非商业使用。商用服务应改用不含它的自定义榜单（`rank_list` 填榜单编号），或先向 Tranco 确认。威胁订阅源也各有条款：Phishing.Database 是 MIT，OpenPhish 的免费版限非商业。URLhaus 的公开下载已经停用，现在要 abuse.ch 的密钥，所以没有做成内置选项。
- 信号的思路来自 [url.vet](https://github.com/urlvet/urlvet)（AGPL-3.0），数据表由它的表转换而来，见 `seesea-core/crates/seesea-vet/NOTICE.md`。
