# 已知限制

这一页列出 seesea 当前做不到或没有验证过的事。每一条都是现状，不是承诺。

## 搜索来源

- 默认参与的内置来源是 Bing、DuckDuckGo（HTML）、Mojeek 和 Wikipedia。Stack Overflow、arXiv、GitHub 只回答特定类型的问题，必须点名才使用（`-s stackoverflow,arxiv,github`）。百度和搜狗因为验证码和超时已移除。
- 抓取型来源容易失效。DuckDuckGo 和 Mojeek 常对云主机和部分家庭网络返回验证码，报告为 `Blocked`；部分网络里 Wikipedia 和 DuckDuckGo 访问不了。只有 arXiv、Stack Overflow 和 GitHub 对真实服务验证过，其余的解析基于样本。
- SearXNG 和 Brave 的解析只用手写样本测试过，没有对真实服务验证。请用 `seesea sources --check` 检查自己的实例。
- 返回验证码或限流的来源，会先暂停 5 分钟，再次被拦则翻倍，最长 1 小时。只剩被暂停的来源时不暂停。

## 页面抓取与抽取

- 抓取页面默认带浏览器式请求头。遇到 403、429 或 503 会换一套浏览器画像并带搜索引擎 Referer 重试，最多共 3 次，遵守 `Retry-After`。只改请求头，不模拟 TLS 指纹，不执行脚本，不破解验证码，所以需要这些的站点（如知乎、百度百科）仍会拒绝。
- 静态 HTML 里没有正文的页面用 Lightpanda 渲染。渲染浏览器被禁止连接私有地址，包括页面脚本发起的请求；它不能配合 SOCKS 代理，也无法越过拒绝 seesea 的服务器。
- 前 N 个候选里读不到的页面会由后面的候选补上，最多补一轮。补过之后仍读不到的页面，只凭标题和摘要的分数排在读过的页面后面。
- 单个页面的下载超时是 10 秒，同时下载 8 个。一个页面超时，整个 `fetch_extract` 阶段至少要 10 秒，除非设置了 `[fetch] enough`（见[配置](config.md)）。
- 抽取器还原表格、上下标，剔除短小的推广块，评测数据见[正文抽取研究](../explanation/extraction-research.md)。

## 排序

- `deep` 模式读取更多页面，但还没有查询改写。
- 语义分数的映射区间（`semantic.range`，默认 0.3 到 0.75）按 bge-m3 调过。别的嵌入模型要自己调；BGE-small 英文大约 0.45 到 0.85。
- 交叉编码器和嵌入模型的权重在 `tools/search-eval` 的 8 个查询上调过，这个集合已接近饱和，差异不应过度解读。
- 第一层的学习没有在标注集上证明能提高 nDCG。同一查询的缓存响应不会随学习更新。主机表上限 2 万。
- 对比 Tavily 的试验里观察到的问题：部分与查询只沾边的页面（例如查询没有限定地区却返回另一个地区的榜单）仍会进入前几名。这类误判要靠带标注的数据集来调。

## 安全

- SSRF 防护：抓取页面用的客户端只连公网。它的解析器把私有地址从每次解析结果里滤掉（回环、RFC 1918、100.64.0.0/10、含 169.254.169.254 的链路本地、ULA，以及内嵌这些地址的 IPv4 映射、NAT64 和 6to4 形式），所以连接时才改变解析结果的域名也拦得住；重定向在发出请求之前就按目标检查。`198.18.0.0/15`（TUN 类代理的 fake-IP 段）视为公网。使用 `--proxy` 时由代理解析，只能检查 URL 和重定向里写出的地址。
- 抽取前先检查页面标记：嵌套超过 128 层的包装元素会被去掉标签、保留内容，超过 10 万个元素的页面在那里截断，一个永不结束的标签会截掉其后的全部内容。嵌套过深或有永不结束标签的页面被当作恶意页面：按读不到处理（排在读过的页面后面，`content_error` 写明原因，主机评分按读不到记录）。元素过多只记录标记，页面内容仍被使用。
- WebSub 只用单元测试和本地 HTTP 测试验证过，没有对真实 hub 测过。

## 多节点

- 一个集群最多两个 flywheel 加一个 witness。数据节点不能横向扩展。
- 复制是异步的，账号修改除外。意外宕机时，令牌桶和用量计数（5 秒）、站点评分（1 分钟）、搜索记录（30 秒）、索引（10 分钟）最近的一小段可能丢失。
- 意外宕机的故障转移窗口约 4 到 5 秒。这段时间里请求变慢或在重试 5 次后失败。
- 多个网关各自统计并发上限和失败密钥次数，同一用户同时在 N 个网关上最多有 N 倍并发。每个请求多一次 flywheel 往返。
- 依赖各机器时钟走得一样快，不要求对时。
- 没有在真实多机或跨机房网络上测试过。`scripts/netns-cluster.sh` 在一台机器上用网络命名空间加 2 ms 延迟模拟。
- 没有注册页、计费和控制台。

## 存储

- 存储只有内存和文件缓存，加上 SQLite（用户库）和按天的 SQLite 文件（本地索引）。没有采用 Turso。
