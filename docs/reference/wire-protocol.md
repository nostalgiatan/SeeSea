# 节点间协议参考：seesea-wire/1

多节点部署里，节点之间用 `seesea-wire/1` 通信。它是 QUIC 之上的应用层协议，不是 HTTP。设计理由见[多节点设计](../explanation/cluster-design.md)。

## 传输

| 项目 | 取值 |
|---|---|
| 底层 | QUIC（UDP），quinn 0.11，rustls 0.23 |
| TLS | 仅 TLS 1.3 |
| ALPN | `seesea/1`，同时是版本号 |
| 地址写法 | `quic://主机:端口`，默认端口 7443 |
| 空闲超时 | 10 秒 |
| 保活 | 每 3 秒 |
| 每条连接的并发流 | 256 |
| 每个节点的打开连接上限 | 512 |

一个请求占一条双向流：客户端写请求帧，服务端写回复帧，然后结束这条流。

## 帧格式

```
tag:u8 | head_len:u32 | body_len:u32 | head | body
```

长度用大端字节序。`head` 是 JSON（可以为空），`body` 是原始字节。请求帧的 `tag` 是操作码，回复帧的 `tag` 是状态码。

帧头上限 64 KiB。帧体上限随操作而定，回复的上限是 64 MiB：

| 操作 | 请求体上限 |
|---|---|
| `Events` | 32 MiB |
| `LearnMerge` | 64 MiB |
| `Http` | 2 MiB |
| 其他 | 64 KiB |

服务端按 256 KiB 一块读取帧体，声明很大的长度本身不占内存。读取一个请求最多 30 秒，处理最多 125 秒。

## 操作码

| 码 | 名称 | 用途 |
|---|---|---|
| 0 | `Ping` | 探活 |
| 1 | `Events` | 搜索节点向 flywheel 推送事件（读过的页面、使用记录、站点评分观测） |
| 2 | `LearnGet` | 读取合并后的站点评分 |
| 3 | `LearnMerge` | 合并站点评分 |
| 4 | `IndexSearch` | 向 flywheel 查询本地索引 |
| 5 | `Http` | 网关转发的用户请求 |
| 6 | `Admit` | 网关向 flywheel 校验密钥并检查额度 |
| 7 | `Charge` | 网关向 flywheel 扣积分 |
| 8 | `Refund` | 退还积分（并发上限拒绝时） |
| 9 | `Replicate` | 跟随者从持有者复制数据：账号、评分、索引、日志 |
| 10 | `Lease` | 写租约的投票和续约 |
| 11 | `Nudge` | 持有者通知跟随者立即复制账号 |

`Charge` 和 `Refund` 按用户名识别用户，因为不同 flywheel 上的用户编号可能不同。

## 状态码

| 名称 | 含义 |
|---|---|
| `Ok` | 成功 |
| `Error` | 失败，头里有原因 |
| `Busy` | 节点并发已满，什么都没做；网关换下一个节点 |
| `Forbidden` | 对端的角色不允许这个操作 |
| `NotLeader` | 本节点不持有写租约；客户端换另一个 flywheel |

## 身份与角色

每个节点有自己的密钥对（`seesea cluster keygen`），证书是自签的。双方握手时都必须出示证书，且其 SHA-256 指纹在对方的 `cluster_peers` 名单里。客户端还要求对方的角色是它所期望的，比如连 flywheel 的必须是 flywheel。

权限看名单里的角色，不看对方自称：

| 对端角色 | 允许的操作 |
|---|---|
| 任何角色 | `Ping` |
| `gateway` | `Http`、`Admit`、`Charge`、`Refund` |
| `search` | `Events`、`LearnGet`、`IndexSearch` |
| `flywheel` | `Replicate`、`Lease`、`Nudge` |
| `operator` | `Events`、`LearnGet`、`LearnMerge` |
| `witness` | 只有 `Ping`；见证节点只回答 flywheel 的 `Lease` 询问 |

吊销一个节点：从 `cluster_peers` 删掉它的那一行。文件改动后（至少间隔 1 秒）自动重读，已建立的连接在下一个请求时被关闭。

## 事件的投递

事件带 `(epoch, seq)` 编号。flywheel 对每个发送者（按证书指纹）和 epoch 记住已应用到哪个编号，重发的批次只应用一次，这个记录保存在状态目录的 `applied.json` 里。

搜索节点发送事件的方式：

| 项目 | 取值 |
|---|---|
| 每批事件数 | 500 |
| 内存队列上限 | 2 万条或 64 MB |
| 超出后 | 写入 `spool` 目录，每个文件约 8 MB，总量最多 2 GB |
| 重启后 | 继续发送 spool 里的内容 |
| 仍超出 | 丢弃最旧的并计数 |

spool 文件在其中所有事件都被确认之后才删除。

## 背压与重试

| 情形 | 行为 |
|---|---|
| 节点并发满 | 立即回 `Busy`；网关换下一个搜索节点，最多试 3 个；全满时回 HTTP 503 加 `Retry-After` |
| 连不上的节点 | 标记不可用 10 秒，期间跳过 |
| 对端回 `NotLeader` 或连不上 | `Failover` 每 0.5 秒重试，最多 5 次 |
| 读请求失败（GET） | 网关换下一个节点重试 |
| 搜索请求的总期限 | 115 秒；flywheel 请求 10 秒 |

客户端会停留在最后应答的 flywheel 上，不会因为原来的主恢复就自己切回去。

## 写租约

两个 flywheel 加一个 witness 组成三个投票方。只有拿到多数票的 flywheel 持有写租约，才处理读写，另一个回 `NotLeader`。

| 参数 | 取值 |
|---|---|
| 投票方的承诺期 | 4 秒内不投给别人 |
| 持有者自认的持有期 | 2.5 秒 |
| 续约间隔 | 0.5 秒 |
| 单次询问的超时 | 1 秒 |
| 启动时 | 指纹较大的节点推迟 2 秒，避免两边同时抢 |

正常停止时持有者发送 `{"release": true}` 主动交出租约。

没有拿到租约的 flywheel 作为跟随者复制数据：

| 数据 | 周期 |
|---|---|
| 账号 | 每 5 秒；持有者回复账号修改前最多等 3 秒让跟随者先拉走（`Nudge`） |
| 站点评分 | 每分钟 |
| 搜索记录（journal） | 每 30 秒，按来源编号去重 |
| 索引条目 | 每 10 分钟 |

## 状态查询

`GET /v1/cluster/status` 返回当前角色和租约状态，见 [HTTP 接口参考](http-api.md#集群状态)。
