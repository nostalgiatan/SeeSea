# 在一台机器上测试集群

`scripts/netns-cluster.sh` 在一台机器上起一整套集群，不需要 root，也不需要 Docker。每个节点放在自己的网络命名空间里，有独立的 IP，通过一个虚拟交换机相连，每一跳加 2 毫秒延迟。

## 前提

- Linux，允许非特权用户命名空间（脚本用 `unshare -Urnm`）。
- 安装了 `iproute2`（`ip`、`tc`）、`curl` 和 `bc`。
- 一个编译好的 `seesea`。

## 运行

```bash
cd seesea-core
cargo build -p seesea-cli
scripts/netns-cluster.sh target/debug/seesea
```

脚本起 6 个节点：两个 flywheel、一个 witness、两个搜索节点、一个网关，然后逐项检查，每项打印 `ok` 或 `FAIL`，最后给出通过和失败的个数。有失败时会打印各节点日志的最后几行。

## 它检查什么

脚本共 18 项检查：

- 网关能看到两个搜索节点；错误的密钥被拒绝。
- 账号接口和搜索经过网关正常工作。
- 两个 flywheel 里恰有一个持有写租约。
- 跟随者拿到了 leader 的搜索日志。
- 创建密钥后立刻强制结束（`kill -9`）leader，这把密钥在新 leader 上可用。
- leader 被强制结束后，跟随者在 8 秒内拿到租约，账号和搜索照常回答。
- 旧 leader 回来后变成跟随者，不会抢回租约。
- leader 与其他节点断开但仍在运行时，它停止写入，另一侧接手，账号经新 leader 回答；网络恢复后仍然只有一个 writer。
- 强制结束一个搜索节点后，另一个回答。
- 30% 丢包下大多数请求仍然成功（QUIC 重传）。
- 一个搜索节点被隔离时，网关返回干净的错误，不会挂起。

## 注意

节点在命名空间里连不上互联网，搜索不会返回网页结果。脚本检查的是集群本身（协议、账号、转发、故障转移和丢包），不是搜索质量。它也不能代替真实多机或跨机房环境的测试。
